# 12 · 多端点回退链 + 操作反思循环

> 两个能力分别借鉴 droidrun 的「provider 无关」和 Mobile-Agent 的「reflection」。
> 都要一个前提：**一个能用的模型端点**（自备，见 README「模型接入」）。

---

## 一、回退链：`llm.py`

### 为什么

单端点一挂，答题、看视频、自动化**整条线全废**，而且报错往往是"没反应"。
回退链把「端点 × 模型」排成顺序，谁先回来用谁。

### 配置：`~/dsh-phone/endpoints.json`

```json
{
  "timeout": 90,
  "retries_per_endpoint": 2,
  "endpoints": [
    {"name": "local", "base": "http://127.0.0.1:8787/v1/chat/completions",
     "key": "local-noop",
     "models": ["deepseek-v4-pro", "glm-5.2"],
     "vision_models": ["glm-5v-turbo"]},

    {"name": "cloud", "base": "https://api.example.com/v1/chat/completions",
     "key": "sk-xxx",
     "models": ["gpt-4o-mini"],
     "vision_models": ["gpt-4o"]}
  ]
}
```

优先级：`环境变量 DSH_ENDPOINTS`（整段 JSON）> `~/dsh-phone/endpoints.json` > 内置单个本地端点。

`vision_models` 单独列：**视觉模型必须和文本模型分开配**，否则识图会静默失败（见 [04](04-识图.md)）。

### 用法

```bash
python ~/dsh-phone/llm.py --ping          # 逐个探活：谁通、谁挂、多少毫秒
python ~/dsh-phone/llm.py "用一句话介绍你自己"
python ~/dsh-phone/llm.py --vision ~/tmp/shot.png "这屏上写了什么"
```

`--ping` 输出：

```
候选链：
  1) local / deepseek-v4-pro
逐个探活：
  OK   local    deepseek-v4-pro   1773ms  '在的'
可用 1 / 1
```

### 什么时候会跳到下一个

| 情况 | 行为 |
|---|---|
| 连接被拒 / DNS 错 / 超时 | 重试 `retries_per_endpoint` 次，仍失败就换下一个 |
| HTTP 400 / 401 / 403 / 404 | **立刻换**（重试没意义：key 错、路径错、模型名错） |
| HTTP 429 / 5xx | 重试（有退避：1s、2s…） |
| 返回空文本 / 结构不是 `choices[0].message` | 当成失败，换下一个 |
| 全部挂掉 | 抛错，并列出每个候选的失败原因 |

### 实测（真机，2026-11-13）

故意把前两个端点写坏，看它会不会自己跳到第三个：

```
$ DSH_ENDPOINTS='{... 死端口(127.0.0.1:9) … 错路径(/v1/nope) … 真端点 … }'
$ python llm.py "只回复四个字：跳到最后"
[llm] 真端点/deepseek-v4-pro  1591ms
跳到最后                        ✅ 自动跳过前两个
```

全挂时的报错（有用，不是干瞪眼）：

```
FAIL: 所有端点都失败了：死端口/m1 <urlopen error [Errno 111] Connection refused>
```

### 也接到了既有脚本

`quiz.py` 的端点和模型现在都能用环境变量覆盖，不用改代码：

```bash
DSH_GW=http://127.0.0.1:8787/v1/chat/completions \
DSH_KEY=local-noop \
DSH_VOTE_MODELS=deepseek-v4-pro,glm-5.2,hy3 \
python ~/dsh-phone/quiz.py solve q.json
```

### 已经接上回退链的脚本

| 脚本 | 走哪条链 | 什么时候会换端点 |
|---|---|---|
| `quiz.py` | `models`（投票/逐项/裁决） | 端点或模型报错、超时、空回复 |
| `vidnote.py` | 逐帧 `vision_models`，汇总 `models` | 同上，而且**逐帧独立**：第 3 帧失败只影响那一帧 |
| `screenwatch.py` | 同上（复用 `vidnote` 的 `vision()` / `post()`） | 同上，抓屏循环不会因为某帧失败而中断 |
| `smartstep.py` | 计划用 `models`，反思用 `vision_models` | 同上 |
| `llm.py --ping` | 只探活，不改任何东西 | —— |

`post(payload)` 还有个保底：**指定模型全挂后会放开模型限制再试一轮**。
这样"端点还活着、但某个模型 id 被下线"时，整条流水线不至于直接死（会换个模型回答，不影响流程）。

> 诚实说明：`vidnote.py` / `screenwatch.py` 的改造**用离线假网关验过回退逻辑（8 项全过，见下）**，
> 但"真机上逐帧识图 + 汇总"的完整流程还没跑（当时电脑和手机不在同一个 Wi-Fi）。
> 真机实测过的是：`llm.py` 的端点回退（前两个写坏 → 自动跳第三个）、`smartstep.py` 干跑、敏感词拦截。

## 二、操作反思循环：`smartstep.py`

### 和"机械重试"的区别

| | 机械重试（`tap-text --verify`） | 反思（`smartstep.py`） |
|---|---|---|
| 失败后 | 原样再点 3 次 | **截图问视觉模型：为什么没成功、现在该点什么** |
| 成本 | 几乎为零 | 每反思一次 = 一次视觉请求 |
| 适用 | 页面加载慢、元素晚出现 | 点错地方、界面和你以为的不一样 |

### 流程

```
读屏(text --click --json) → 模型给一个动作 → 执行 → 复核界面指纹
                                                    ├─ 变了 → 下一步
                                                    └─ 没变 → 截图 → 视觉模型给「原因 + 修正动作」
                                                                        → 执行修正 → 继续
```

### 用法

```bash
# 先干跑：只读屏、只打印计划，绝不点屏幕（强烈建议先这样）
python ~/dsh-phone/smartstep.py --goal "打开设置，进入显示，把深色模式打开" --dry-run

# 真跑
python ~/dsh-phone/smartstep.py --goal "..." --max-steps 10

# 关掉反思（退化成机械重试，省 token）
python ~/dsh-phone/smartstep.py --goal "..." --no-reflect

# 把每步计划和反思存下来复盘
python ~/dsh-phone/smartstep.py --goal "..." --plan-out ~/tmp/plan.json
```

干跑实测输出（真机）：

```
[llm] local/deepseek-v4-pro  2163ms
目标：把当前页面的标题读出来
模式：干跑（不点屏幕），失败会反思
[1] 计划 {"act": "done", "why": "标题为'…'"}  // 已经可以直接读出
[1] 结束：标题为'…'
轨迹已存：~/tmp/plan_demo.json
```

### 安全三道闸

1. **敏感词拦截**：动作里出现 `支付 / 付款 / 转账 / 验证码 / 密码 / 人脸 / 卸载 / 格式化 / 注销 / 解绑` → 立即中止（实测：`{"act":"tap-text","text":"确认支付"}` 被拦，`设置` 放行）。
2. **`--dry-run`**：只读屏不点屏幕，先看清它想干什么。
3. **步数上限**：默认 8 步，防死循环。

### 局限（照实说）

- 反思要**视觉模型**；只有文本模型时这条链等于不存在（会报错跳过）。
- 反思可能**幻觉**：它看截图猜原因，猜错就带着你走偏。所以 `--dry-run` 先看一遍很重要。
- 每次反思都多花一次视觉请求，**贵**。日常操作用 `tap-text --verify` 就够。
- 它不是通用 Agent：只做"点一点、等一下、看一眼"，不做多 App 长流程规划。

## 三、这套东西的边界

- 微信这类**控件树为空**的 App，两条链路都无效（反思也无从下手，因为读屏是空的）。
- 模型给的坐标/文字必须来自**当次读屏结果**，prompt 里已经强制要求；但模型仍可能编，所以每次执行后都复核。
- 真正的自动化不是"让模型自由发挥"，而是"**把不确定性收敛到可验证的一步**"：一次一个动作、做完就验、错了就停或反思。
