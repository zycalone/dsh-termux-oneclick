# 13 · 开会自动做纪要（一条命令，你不用管手机）

> 这一篇是**踩坑之后的反向设计**。之前的做法是「边开会边和手机上的 dsh 聊天，让它总结腾讯会议」，
> 结果显示很麻烦：**你每敲一条命令，浏览器就把会议挤到后台**，截到的三张全是 dsh 自己的界面；
> 切回会议还得靠 `monkey` 拉 App。这件事的本质是：**手机只有一块屏幕，你看会议时就没法看 dsh**。

## 1. 正确姿势：开会前敲一条，散会回来看结果

```bash
python ~/dsh-phone/meetnote.py                 # 默认每 20 秒看一次，前台是腾讯会议才截
# ……正常开会，手机放桌上不用碰……
# 回 Termux 按 Ctrl+C → 自动生成会议纪要
```

产物（按开始时间建目录）：

```
~/tmp/meet/20261113-2311/
├── 时间线.md      # 每屏一条：时间 + 标题 + 要点 + 画面原文
└── 会议纪要.md    # 退出时自动归纳：一句话结论 / 分主题要点 / 资料链接数字 / 待办
```

常用参数：

| 参数 | 用途 |
|---|---|
| `--interval 15` | 15 秒看一次（默认 20） |
| `--pkgs com.tencent.wemeet.app,com.tencent.mm` | 允许截图的前台包名，逗号分隔（微信开会也可以） |
| `--minutes 45` | 45 分钟自动收工，不用守着 |
| `--no-summary` | 只要原始时间线，不生成纪要 |
| `--summarize ~/tmp/meet/20261113-2311` | **不录新的**，只把已有时间线重新归纳一遍 |
| `--keep-awake` | 开会期间强制屏幕常亮（**截图抓的是当前屏幕，锁屏就什么都抓不到**），退出自动恢复 |
| `--keep-frames` | 保留截图（默认读完就删，一小时约 90MB → 0） |
| `--dry-run` | 只打印"截到了什么"，不调模型（0 token） |

## 2. 三个省 token 的设计

开会一小时 180 帧，全送视觉模型既贵又慢。所以：

1. **只在前台是会议 App 时才截**：前台是浏览器/微信 → 直接跳过，一行 `[跳过] 前台是 …` 带过。
   这也顺手解决了"截到自己界面"的坑。
2. **画面 md5 不变就不读图**：PPT 不翻页时一帧都不花。
3. **内容不变也让模型自己说**：md5 会变但内容没变（时钟、弹幕、鼠标在动）时，
   把"上一次记录"塞进 prompt，模型判定相同就只回 `{"kind":"same"}`，同样不写进时间线。

## 3. 实测记录（真机，Termux）

拿 B 站视频画面当"会议画面"跑了一遍（`--pkgs tv.danmaku.bili --interval 6 --max-frames 2`）：

```
=== meetnote ===
只在前台是 tv.danmaku.bili 时截图；每 6 秒看一次
输出目录：~/tmp/meet-test/20261113-2311
模型自检：local/deepseek-v4-pro
[23:11:19] 记下第 1 屏：原来《后会友期》选角面试
[23:11:34] 记下第 2 屏：知情人曝《后会友期》选角内幕，面试过程曝光，场面好尴尬！
抓够 2 帧，收工
时间线：~/tmp/meet-test/20261113-2311/时间线.md（2 屏，抓了 2 帧）
会议纪要：~/tmp/meet-test/20261113-2311/会议纪要.md
（用 local/deepseek-v4-pro 生成）
```

生成的时间线长这样：

```markdown
## [23:11:19] 第 1 屏 · 原来《后会友期》选角面试

- 知情人曝《后会友期》选角内幕，面试过程曝光，场面好尴尬！

> 原文：`原来《后会友期》选角面试 … 16.6万播放`
```

纪要则是标准的四段式（一句话结论 / 按主题分节 / 出现的资料链接数字 / 待办），
且明确写了"不要编造时间线里没有的内容"。

另外两条路径也实测过：

```
# 前台不是会议 App → 一直跳过，0 帧 0 token
[跳过] 前台是 tv.danmaku.bili，不是会议
时间线：~/tmp/meet-skip/…/时间线.md（0 屏，抓了 0 帧）

# 事后重新归纳（换模型、换提示词都行）
python ~/dsh-phone/meetnote.py --summarize ~/tmp/meet/20261113-2311
会议纪要：~/tmp/meet/20261113-2311/会议纪要.md
```

## 4. 它能做什么、不能做什么（诚实版）

**能**：抓共享 PPT / 文档 / 白板上的文字，按时间排成时间线，最后归纳成纪要。
PPT 每翻一页记一条，翻得快也不会乱（丢帧只丢中间那几秒）。

**不能**：

- **听不到声音**。没有人说话内容的转写，只有屏幕上出现过的字。要"谁说了一句什么"，得靠会议自带的
  「云录制 / 转写」导出文字稿，再把文字稿丢给 dsh 总结 —— 那条路更准，但有主持人才开得了录制。
- **你切走屏幕就漏**。前台一旦不是会议 App 就跳过（这是故意的，避免抓到你自己在翻的微信）。
  如果会议必须靠"听"，画面又一直没变，时间线会很少。
- ⚠️ **腾讯会议的共享画面在部分版本会被安全策略挡**（截图是黑屏/只有水印）——
  遇到这种情况 `时间线.md` 会是空的，改成用会议自带的录制。
- ⚠️ 会议窗口若是**悬浮小窗**，`mCurrentFocus` 可能仍报别的包名，此时把 `--pkgs` 加上那个包名，
  或者干脆把会议放到全屏。

## 6. 不想截图？三条「非截图」的路（都实测过）

先说结论：**Android 不给「直接读另一个 App 的内容」这扇门**。
App 私有数据在 `/data/data/<包名>/`，只有它自己或者 root 能进；`adb shell` 是 `shell` 用户，
被 SELinux 挡在外面。所以"直接抓取"只能走下面三条，各有各的天花板。

### 路线 A：无障碍树（本项目已实现，`--a11y`）

界面上的文字，系统本来就以「无障碍节点」的形式暴露给读屏软件，不用截图、不用模型：

```bash
python ~/dsh-phone/meetnote.py --a11y        # 树里有字就用树，读不到才截图
python ~/dsh-phone/meetnote.py --a11y-only   # 永不截图
```

真机实测（B 站页面当测试对象）：

```
[23:19:12] 记下第 1 屏：22 条新文字（没花视觉 token）
[23:19:23] 文字没变，跳过
时间线：~/tmp/meet-a11y3/…/时间线.md（1 屏，抓了 0 帧）
--- png 数量（应 0）---
0
```

- **成本**：`uiautomator dump` 一次约 **3 秒**，产出 24 条文字、**0 张图、0 视觉 token**
- **拿得到**：会议里的聊天、成员列表、按钮文字、共享文档的正文文字、说话人字幕（如果有）
- **拿不到**：画在图片/视频里的共享 PPT（它是个 SurfaceView，树里没有文字），
  以及被 `FLAG_SECURE` 保护的窗口（腾讯会议开会时常见，树会空）
- 所以 `--a11y` 的策略是：**树里有字就白嫖，没有就退回截图**

### 路线 B：让会议 App 自己产出文字（最准，也是唯一能听到声音的）

腾讯会议 3.47 自带 **云录制 / 智能纪要 / 转写**（它持有 `RECORD_AUDIO` 和
`FOREGROUND_SERVICE_MEDIA_PROJECTION` 权限，这就是它自己能录屏录音的凭据）。
会后导出 `txt` / `docx` / `pdf` 文字稿，再交给 dsh 总结：

```bash
# 文字稿丢到手机上任意位置，然后
python ~/dsh-phone/read_docx.py ~/tmp/会议转写.docx   # 或直接让 dsh 读 txt/md
```

- **优点**：有"谁说了什么"，是最完整的纪要来源；不受截图黑屏影响
- **限制**：需要主持人开录制 / 免费版有次数限制；你不能自己单方面开

### 路线 C：录屏一段，事后抽帧

```bash
adb shell screenrecord --time-limit 0 --bit-rate 4M /sdcard/meet.mp4   # Ctrl+C 停
python ~/dsh-phone/vidnote.py /sdcard/meet.mp4 --interval 30
```

- **优点**：一条命令连续录，不会像定时截图那样漏掉中间几秒
- **缺点**：① `screenrecord --help` 里**没有音频选项**（Android 14 实测），录不到声音；
  ② 本质仍是像素，受 `FLAG_SECURE` 影响；③ 一小时约 1-2GB，得记得删

### 三条路怎么选

| 你可能的情况 | 走哪条 | 实测成本 |
|---|---|---|
| 想要"谁说了什么"的完整纪要 | **B 云录制/转写** + dsh 总结文字稿 | 0 截图，最准 |
| 没权限开录制，只想记录屏幕上的要点 | **A `--a11y`**（能拿到文字时） | 3s/次，0 token |
| 共享的是 PPT 图片、树上读不到 | A 自动退回**截图**（默认模式） | 一次读图 |
| 想一镜到底、事后慢慢看 | C `screenrecord` | 磁盘换省心 |

> 一句话：**要"不截图"，就不要盯着屏幕，而是让会议 App 把文字交出来。**

## 8. 如果你只是参会者（拿不到录制权限）

这是最常见也最憋屈的情况，先把结论说清：

| 想做的事 | 能不能 |
|---|---|
| 开云录制 / 转写 | ❌ 一般只有**主持人/联席主持人**能开；会后「我的录制」你那边也没有 |
| 腾讯会议手机端本地录制 | ❌ 客户端没有这个入口（PC 端有，且通常也要主持人允许 ⚠️） |
| 用 dsh 录会议音频再转写 | ❌ 实测：端点没有 `/v1/audio/transcriptions`（404）、模型列表里没有任何 whisper/asr 模型；Android 10+ 也禁止 App 内录 |
| 让 dsh 读屏幕上的内容 | ✅ **这才是参会者的可行路线** |

所以参会者的流程就是**画面流**：

```bash
# 会前，一条命令（默认截图模式，15 秒看一次，屏幕常亮）
python ~/dsh-phone/meetnote.py --pkgs com.tencent.wemeet.app --interval 15 --keep-awake

# 开会：手机放桌上，进会议正常听；共享 PPT 每翻一页自动记一条
# 散会：回 Termux 按 Ctrl+C
# 产物：~/tmp/meet/<时间>/时间线.md + 会议纪要.md
```

要点：

- **手机屏幕得留在会议界面**。截图抓的是当前前台，切到微信/浏览器就跳过（这正是为了不干扰你）。
- **`--keep-awake` 很关键**：不常亮的话息屏后截到的就是锁屏/黑屏。它用 `svc power stayon true` 实现，退出自动 `false`（实测有效）。
- **共享 PPT 是图片，无障碍树里没有文字**，所以参会者默认用截图模式；只有会里主要是聊天/文档正文时，`--a11y` 才划算。

### 顺带修的一个坑：别把"按钮墙"当成会议内容

`--a11y` 早期版本只要树里有字就走文字树。但参会者看到的界面通常只有
`静音 / 摄像头 / 共享屏幕 / 成员 / 更多` 这一圈按钮 —— 于是它以为"有内容"，
**从此再也不截图，共享的 PPT 全程漏掉**。

现在加了内容判定 `contentish()`：按钮词被过滤，至少要两条"像正文"的文字（连续中文 ≥6 字或长度 ≥12）
才认。实测：

```
会议按钮墙（应判 0，退回截图）        contentish=0
共享文档正文（应判 >2）              contentish=3
聊天区发言（应判 >2）                contentish=3
混合（按钮 + 一页 PPT 文字）          contentish=2
```

判不过就自动退回截图，不会再把一场会记成一片空白。

### 想听声音怎么办（唯一现实的两条）

1. **求主持人开录制/转写**，会后再走 [docs/14](14-转写稿变笔记.md) —— 最完整，但要人配合。
2. **自己录音**：手机外放 + 录音机（或另一台设备）录下来 → 找一个带 ASR 的服务转成文字（本项目的端点不含 ASR，
   需要一个 OpenAI 兼容的 whisper 端点）→ 再交给 `minutetool.py`。

## 5. 和"边聊边看"比，为什么这个省事

| | 边开会边问 dsh（旧） | `meetnote.py`（新） |
|---|---|---|
| 你要操作 | 不断发消息、确认、切前台 | **一条命令，之后不碰手机** |
| 会议会不会被挤后台 | 会，每敲一次就挤走 | 不会，脚本只在后台截图 |
| 切回会议 | 深链接失效 → 试 `am start` → `am task move-to-front`（Android 14 已砍）→ `monkey` 才成 | 不需要切 |
| 结果 | 只总结了当时那一页 | 整场时间线 + 纪要文件 |
