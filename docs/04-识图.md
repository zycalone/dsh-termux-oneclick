# 04 · 识图（为什么它说"看不见图片"）

## 一句话结论

**模型必须声明支持图片输入，否则图片会被静默丢弃**，你只能看到 `[image]` 之类的占位符。

在 `config/cordis.patch.yml` 里这样写：

```yaml
- id: llm-pi-ai
  config:
    providers:
      openai:
        models:
          - id: glm-5v-turbo          # 换成你那边的视觉模型 id
            name: GLM-5V Turbo (识图)
            input: [text, image]      # ← 关键，少了这行就等于没有视觉
```

---

## 判断是不是"模型不支持"

| 现象 | 原因 |
|---|---|
| 模型说"我无法查看图片/我看不到" | 该模型没声明 `image`，或端点不认 `image_url` |
| 报 `does not declare image input` | 同上，dsh 主动拦下了 |
| 图片下载失败 / 413 | 图太大：先压到长边 720~1024，JPEG 质量 3~5 |
| 中文小字识别错 | 图太糊：先 2× 放大再送，或裁切到目标区域 |

## 命令行验证（不经过 dsh，直连端点）

```bash
IMG=/sdcard/Download/test.png
IMG=$IMG python - <<'PY'
import base64, json, os, urllib.request
p = os.environ["IMG"]
b64 = base64.b64encode(open(p, "rb").read()).decode()
body = {"model": "glm-5v-turbo", "messages": [{"role": "user", "content": [
    {"type": "text", "text": "把图上的文字全部读出来"},
    {"type": "image_url", "image_url": {"url": "data:image/png;base64," + b64}}]}]}
req = urllib.request.Request(os.environ["GW"], data=json.dumps(body).encode(),
      headers={"Content-Type": "application/json",
               "Authorization": "Bearer " + os.environ.get("KEY", "sk-none")})
print(json.load(urllib.request.urlopen(req, timeout=180))["choices"][0]["message"]["content"])
PY
```

（`GW=http://127.0.0.1:8787/v1/chat/completions`）

能跑通说明端点没问题，问题就出在 dsh 的模型声明上。

## 好用的套路

- **抄题**：截图 → 让模型"逐字抄写题干与全部选项，不要解题"，再单独让它作答。两步比分一步准。
- **读界面**：问"这个界面有哪些按钮、分别在哪里、能不能点"，比"这是什么"有用。
- **看 PPT**：图先放大到 1600 宽，再问"把这一页的标题、正文、公式抄下来"。
- **算力省钱**：先让视觉模型只做 OCR，再用便宜的文本模型做推理。
