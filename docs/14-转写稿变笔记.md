# 14 · 转写稿 → 会议纪要 / 学习笔记（两种模式）

> 这是[路线 B](13-开会自动做纪要.md) 的收尾工具：会议 App 云录制 / 转写导出文字稿之后，
> 用一条命令变成能直接看的东西。**全程不截图、不吃视觉 token。**

## 1. 一条命令，两种产物

```bash
python ~/dsh-phone/minutetool.py 转写稿.txt                   # 默认：会议纪要
python ~/dsh-phone/minutetool.py 讲座.srt --kind lecture       # 讲座 → 学习笔记
python ~/dsh-phone/minutetool.py 录音.docx --kind auto         # 让模型自己判断是哪种
```

| 模式 | 产出结构 | 适合 |
|---|---|---|
| `--kind meeting` | 一句话结论 / 结论与决策 / **待办表（谁·做什么·何时）** / 数字与资料 / 风险与不同意见 | 例会、项目会、班委会、部门会 |
| `--kind lecture` | 这次讲了什么 / 核心概念与定义 / 公式结论步骤 / 例子与例题 / **可能考的点和问法** / **容易混容易错** / 我没听懂或稿子里缺失的部分 | 讲座、课堂、培训、网课 |
| `--kind auto` | 先看开头判断，再走上面其中一条 | 拿不准的时候 |

## 2. 为什么"讲座"要单独一套提示词

同一份稿子，会议关心**谁要做什么**，讲座关心**你学会了什么、会怎么考**。所以讲座模式的提示词里写死了三件事：

1. **不许补充稿子以外的知识** —— 提示词原话是"你不是在补课"。模型最爱自作主张补定义，那样笔记就不是这场讲座的了。
2. **单独列"可能考的点和问法"** —— 把讲者的"这个是考点""这个常考"捞出来，转成题目形式。
3. **单独列"我没听懂或稿子里缺失的部分"** —— 转写稿必然有听不清、跳过的段落，诚实标出来，比编一段通顺的假内容有用。

## 3. 支持什么格式（手机上没有额外依赖也能跑）

| 格式 | 怎么读 |
|---|---|
| `.txt` `.md` `.csv` `.log` | 直接读 |
| `.srt` `.vtt` | 自动剥掉时间轴、序号、`WEBVTT` 头，并合并相邻重复行（自动字幕常滚动重复） |
| `.docx` | 用标准库 `zipfile` 解压读 `word/document.xml`，**不需要 python-docx** |
| `.pdf` | 需要 `pdftotext`（Termux: `pkg install poppler`），没有会明确提示 |
| 标准输入 | `cat 稿子.txt \| python ~/dsh-phone/minutetool.py -` |

## 4. 长稿怎么处理：先分段提取，再合并

一场两小时的讲座转写成文字大概 2-4 万字，塞不进一次请求。所以：

```
转写稿 ──切段(默认 5000 字/段)──> 每段提取要点 ──> 合并成一份结构化笔记
```

- 每段的提示词都是"只提取这一段里明确说过的"，避免模型跨段脑补；
- 合并那一步明确要求"合并重复项 / 保留数字和人名原文 / 缺信息就写未提及"；
- 两段产物都会落盘：`<kind>.md`（成品）和 `分段提取.md`（中间结果，方便你核对有没有漏）。

## 5. 实测（真机 Termux，本地端点 `local/deepseek-v4-pro`）

**讲座模式**（SRT 字幕 → 一页二叉树课）：

```
=== minutetool ===
稿子：668 字（~/sample_lecture.srt）
分 1 段，模式：lecture
  [1/1] 668 字 → deepseek-v4-pro
成品：~/tmp/notes-test/二叉树讲座-20261113-2323/lecture.md
```

产出的笔记里，讲者随口说的"这个是考点，考试一定会问…"被准确转成了题目：

```markdown
## 可能考的点和问法
- 二叉树和度为 2 的有序树有什么区别？
  - 关键差别：二叉树可以是空树。
- 二叉树三个性质的计算或推导，尤其是性质三的推导。
- 为什么只给先序和后序不能唯一确定二叉树？
```

"我没听懂或稿子里缺失的部分"也没编：

```markdown
- 性质三的推导过程稿子里只提到"你们要会"，但没有给出具体推导步骤。
- 三种遍历的非递归实现只提到用栈实现，但没有给出具体代码或思路。
```

**会议模式**（txt → 社团例会）待办表直接可用：

```markdown
| 谁 | 做什么 | 时间 |
| 主持人 | 发排班表到群里 | 明天中午前 |
| 张涛 | 把八十元海报发票给主持人 | 未提及 |
| 王芳 | 讲社团介绍 | 下周三晚上七点 |
| 有垫钱的人 | 把票给主持人 | 最晚二十三号 |
```

**auto 判断**（拿会议稿试）：`{"kind":"meeting","why":"内容为社团负责人主持的例会，围绕排班、报销、培训安排进行任务分工与确认。"}` ✅

**强制多段**（`--chunk 200`）：正确切成 2 段 → 分别提取 → 合并，内容不丢。

## 6. 边界

- ⚠️ **它只处理文字稿**。稿子本身要靠会议 App 的云录制/转写，或你自己录音后转写；
  dsh 在手机上**拿不到会议音频**（Android 10+ 禁止 App 内录，`screenrecord` 无音频选项，实测确认）。
- ⚠️ 转写稿本身的错别字（人名、术语同音错）会原样带进来；数字和专有名词建议扫一眼。
- 稿子特别脏（多人抢话、大量"嗯""那个"）时，分段越多、合并越容易丢细节；`--chunk 8000` 更稳。

## 7. 三件套怎么串起来

```bash
# 1) 开会：会议 App 里开云录制（或会后从「我的录制」导出）
# 2) 导出文字稿到手机，比如 ~/tmp/会议转写.txt 或 .docx
# 3) 一条命令出纪要
python ~/dsh-phone/minutetool.py ~/tmp/会议转写.docx --kind auto --title "11月项目会"
# 4) 想改口味就再跑一次，换 --kind，不用重新转写
python ~/dsh-phone/minutetool.py ~/tmp/会议转写.docx --kind lecture
```
