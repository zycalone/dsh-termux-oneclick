# 05 · 满分答题流水线（quiz.py）

单个模型答选择题，**有 5%~15% 的题会自信地答错**。要接近满分，靠的不是更聪明的模型，而是**多模型独立投票 + 冲突时逐项判定 + 检索兜底**。

`scripts/phone/quiz.py` 就是这套流水线。

---

## 用法

### 单题

```bash
python ~/dsh-phone/quiz.py one "以下哪个是质数？" "9" "15" "17" "21"
python ~/dsh-phone/quiz.py one "下列说法正确的是" "A项" "B项" --multi   # 多选题
```

输出：结论字母 + 选项原文 + 置信度（高/中/低）。

### 整套题

1. 抄题，写成 JSON（**选项不要带 A/B/C 前缀**）：

```json
[
  {"id":"1","type":"single","q":"题干原文","options":["选项1","选项2","选项3","选项4"]},
  {"id":"2","type":"multi","q":"多选题题干","options":["甲","乙","丙","丁"]},
  {"id":"3","type":"judge","q":"判断题题干"}
]
```

2. 跑：

```bash
python ~/dsh-phone/quiz.py solve ~/tmp/q.json
```

---

## 它到底做了什么

1. **多模型独立投票**：把同一道题发给若干个不同厂商/型号的模型，各自独立作答。
2. **一致性判定**：票数一致 → 高置信度；分歧 → 进入下一步。
3. **逐项判定**（多选题必走）：把每个选项单独问一遍"这一项选不选"，避免漏选/多选。
4. **检索兜底**：仍不一致时，用题干原文去搜索引擎/题库找答案作为参考。
5. **低置信度明确标出**，绝不假装确定。

---

## 使用纪律（很重要）

- **按选项原文点，不要按字母**：平台经常打乱顺序。
- **一题都不能空**，多选要选全。
- 题间停顿 **15~40 秒**：一次性秒答会被判作弊。
- **搞清计分规则**：按「平均分」计分的课，重做会拉低均分；按「最高分」才可以重做。
- **提交前把答案清单给用户过目**，用户说提交再点。
- 拿不准的题**单独告诉用户"这题没把握"**，附候选。

## 配置模型

`quiz.py` 顶部的模型列表按你的端点改：

```python
MODELS = ["deepseek-v4-pro", "glm-5.2", "your-model-a", "your-model-b", "your-model-c"]
GW = os.environ.get("DSH_GW", "http://127.0.0.1:8787/v1/chat/completions")
KEY = os.environ.get("DSH_KEY", "sk-none")
```

模型越**异构**（不同厂商）越好；同一个模型问五遍没有意义。
